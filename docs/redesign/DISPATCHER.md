# Для Диспетчера: новая визитка Никиты (11.10)

Сигнал старта - сообщение Никиты **«Начинай визитку»**. До него ничего не начинать.

Если в это время идут другие задачи (Almanac, лэндинг), открытые PR по ним довести до мержа. Новых задач по ним не брать, пока идёт визитка, если Никита не скажет иначе.

## Что делаем

Переделываем визитку `Sorakiel/sorakiel.github.io` **точь-в-точь по `reference/portfolio.html`** на React 19 + TypeScript + Vite.
- Полная спецификация: **`SPEC.md`** - идея, что удалить в репозитории, структура кода, токены, все разделы с поведением и таймингами, инспектор, адаптив, мета, доступность, приёмка, тесты, план из 8 PR.
- Эталон по частям: `reference/src/styles.css`, `reference/src/main.js`, `reference/src/markup.html`.
- Данные проектов готовы: `reference/data/projects.ts`. Скриншоты проектов: `reference/assets/shots/`.
- Скриншоты эталона: `reference/img/` (`d` = 1440×900, `m` = 390×844, светлая и тёмная). Записи: `reference/video/`.

Коротко о смысле: швейцарская сетка, графит и фиолетовый, и встроенный инспектор элементов - по клавише I страница показывает, как она свёрстана. Работы - настоящие скриншоты, строки раскрываются в подробные карточки, по клику скриншот открывается на весь экран.

## Что сделать по сигналу

1. Прочитать `SPEC.md` целиком. Открыть `reference/portfolio.html` в Chromium: дождаться вступления, пройти страницу, раскрыть строки, открыть лайтбокс, сменить тему, включить инспектор клавишей I. Посмотреть обе записи из `reference/video/`.
2. Клонировать `Sorakiel/sorakiel.github.io` рядом с остальными проектами. Проверить: `main` чистый, `npm install && npm run build` проходит. Создать ветку **`redesign`** от `main`. Все PR идут в `redesign`, не в `main`: `main` и `gh-pages` - живой сайт.
3. Положить этот пакет в репозиторий как `docs/redesign/` первым коммитом PR 1, чтобы у всех был один эталон.
4. Добавить в `COORDINATION.md` раздел «Визитка»: кто что делает, очередь мержа, зоны файлов.
5. Раздать задачи исполнителям (у каждого свой worktree `sorakiel.github.io`). Предложение по распределению, менять по ситуации:

| Исполнитель | PR из `SPEC.md` §13 |
| --- | --- |
| Вега | 1 (основа и заглушки всех разделов) → 2 (шапка, тема, герой) → 6 (инспектор) |
| Орион | 3 (список работ, превью у курсора, лайтбокс) → 7 (адаптив и появление при прокрутке) |
| Лира | 4 (кейсы) → 5 (обо мне и контакты) → 8 (доступность, скорость, тесты) |

   PR 1 первым и один. Пока он не смержен, Орион и Лира разбирают свои разделы по эталону и начинают ветки от ветки PR 1.
   После мержа PR 1 работа параллельная. Каждый правит только свои компоненты и свой CSS:
   - **Вега:** `Header`, `Hero`, `lib/theme.ts`, `overlays/Inspector.tsx`, `lib/inspector.ts`, `lib/intro.ts`, `header.css`, `hero.css`, `inspector.css`.
   - **Орион:** `Work`, `ProjectRow`, `ProjectMedia`, `ProjectFacts`, `Peek`, `Lightbox`, `work.css`, `peek.css`, `lightbox.css`.
   - **Лира:** `Case*`, `About`, `Stack`, `Contact*`, `Toast`, `case.css`, `about.css`, `contact.css`, `toast.css`.

   Общие файлы (`tokens.css`, `base.css`, `App.tsx`, `UIContext.tsx`, `lib/env.ts`, `data/*`) после PR 1 меняет только Вега. Остальные просят через Диспетчера.
   PR 7 (адаптив) правит медиазапросы во всех CSS-файлах: Орион берёт его последним, когда разделы смержены, и согласует с владельцами файлов.

6. Сообщение исполнителю (вставить имя, номера PR и зону):

```

в тех же точках, что reference/img, 1440×900 и 390×844, светлая и тёмная;
для анимаций - запись рядом с reference/video (SPEC.md §11).
Conventional Commits, описание PR на русском, никаких упоминаний ИИ.
```

## Как принимать

- Каждый PR - скриншоты сайта и эталона рядом в одинаковых точках, 1440×900 и 390×844, обе темы, плюс запись для всего, что двигается. Пока разница видна глазом - не мержить.
- Тексты сверять с `markup.html` и `projects.ts` дословно, включая короткий дефис вместо тире.
- После PR 8 на всей странице: 360 px без горизонтальной прокрутки, reduced motion, Lighthouse mobile (скорость ≥ 90, доступность ≥ 95), FPS с инспектором при 4-кратном замедлении CPU не ниже 55, клавиатура.
- Если эталон и `SPEC.md` расходятся, прав эталон.

Если нет - присылать скриншоты и запись рядом с эталоном.

## Что нести Никите

Только это, одной строкой:
- «Визитка начата» после старта.
- Превью или скриншоты, когда готовы шапка, герой и список работ (PR 1-3), и когда готова вся страница.
- Вопросы, которые нужны до релиза, одним сообщением: ссылка на резюме PDF, фото для «Обо мне» (до тех пор заглушка), текст `meta description`.
- **Мерж `redesign` в `main` и `npm run deploy` - только после «да» Никиты**: это публикация сайта.
- Любые правки текста, ссылок, цифр и дат - только с его «да».
- Настоящие блокеры.

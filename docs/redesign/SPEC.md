# Визитка Никиты - спецификация (v1, 11.10.2026)

Репозиторий: `Sorakiel/sorakiel.github.io` (старая визитка, React + TypeScript + Vite, публикуется на GitHub Pages из ветки `gh-pages`).
Эталон: `reference/portfolio.html` - откройте в Chromium и пройдите целиком: всё кликается, клавиша `I` включает инспектор.
Этот документ - единственная спецификация сайта. `DISPATCHER.md` описывает только порядок работы.

## 0. Главное правило

Сайт должен выглядеть и вести себя **точь-в-точь как `reference/portfolio.html`**. Это не «по мотивам». Каждый экран сверяется со скриншотами из `reference/img/` и записями из `reference/video/` при тех же размерах окна. PR не открывается, пока разница видна глазом.

Эталон собран одним файлом ради удобства просмотра. В репозитории его нужно разложить на React-компоненты (§4), а не вставлять целиком через `dangerouslySetInnerHTML`.

Тексты брать из эталона **дословно**: `reference/src/markup.html` и `reference/data/projects.ts`. Менять формулировки, ссылки, цифры и даты можно только с «да» Никиты. Во всех текстах короткий дефис `-`, длинного тире нет.

## 1. Идея

Визитка frontend-разработчика без шаблонных «карточек навыков». Швейцарская сетка на 12 колонок, графит и один фиолетовый акцент. Главная фишка - **встроенный инспектор элементов**: по клавише `I` страница показывает, как она свёрстана. Видны сетка, отступы и поля, реальные размеры, шрифт, цвет и имя компонента, как в DevTools.

Работы показаны настоящими скриншотами, без нарисованных макетов. Тон спокойный и деловой: без «магии», без эмодзи, без капса в тексте, кроме мелких моноширинных подписей.

Светлая тема по умолчанию, тёмная зеркалит её. Тема берётся из системы, пока пользователь не выбрал сам.

Закрывается по клику мимо картинки, по «×» и по Esc. При открытии фокус переходит на «×», при закрытии возвращается на скриншот. Пока лайтбокс открыт, страница не прокручивается. Проявление .25s. Пока включён инспектор, лайтбокс не открывается.

### 6.9 Тема
Кнопка темы переключает светлую и тёмную и сохраняет выбор в `localStorage['nv-theme']`; без сохранённого выбора тема берётся из системы.
Смена идёт через `document.startViewTransition`: новая тема раскрывается кругом из центра кнопки до дальнего угла экрана за 550 ms по `cubic-bezier(.2,.8,.2,1)` (анимация `clip-path` на `::view-transition-new(root)`). Без поддержки View Transitions или при reduced motion тема меняется сразу.
Тему применять до первой отрисовки (маленький inline-скрипт в `index.html`), чтобы не было вспышки.

### 6.10 Появление при прокрутке
Только при поддержке `animation-timeline: view()` и без reduced motion; иначе всё просто видно.
`.rv` (строки проектов, кейсы, портрет, текст и стек «Обо мне»): `opacity 0, translateY 28px` → норма на отрезке `entry 0% - entry 55%`.
`.big`: `letter-spacing 0, opacity .3` → норма на отрезке `entry 0% - cover 45%`.

## 7. Инспектор

Главная фишка сайта. Логика - на чистом DOM API в `lib/inspector.ts`. React рендерит только пустые слои оверлея один раз.
**На движение мыши, прокрутку и кадры нельзя трогать стейт React.** Всё идёт через refs, `requestAnimationFrame` и `transform`, иначе каждое движение мыши перерисовывает дерево и HUD показывает просадку FPS.

### 7.1 Включение
- Кнопка в шапке или клавиша `I`. Работает в русской раскладке (`ш` и `Ш`), не срабатывает в полях ввода и с модификаторами. `Esc` выключает.
- На `<html>` ставится класс `inspect`, у кнопки `aria-pressed="true"` и акцентная заливка. Тост: «Инспектор включён: наведите на любой элемент».
- Пока инспектор включён: видна сетка 12 колонок поверх страницы (`.grid-ov`, заливка `--c` 10% и края 45%). У элементов с `data-ins` пунктирная обводка и фиолетовая плашка с подписью над левым верхним углом. В `main` курсор-прицел. Внизу слева HUD.

### 7.2 Наведение и клик
- `pointermove` (кроме touch) берёт `e.target`. Пропускаются шапка, сами оверлеи, тост, превью, `body`, `html`, `main`.
- Клик в режиме инспектора перехватывается в фазе capture (`preventDefault` и `stopPropagation`) и выбирает элемент. Ссылки не открываются, строки не раскрываются. На телефоне элемент выбирается тапом (скрин `m-*-10-inspector-tap`).
- Три рамки как в DevTools:
  - margin - рамка с толщиной границ, равной отступам, цвет `--m` 55%;
  - padding - то же с полями, `--p` 60%;
  - content - заливка `--c` 45%.

### 7.3 Подсказка
Тёмная плашка `#1E2128`, моноширинный 11 px, максимум 360 px. Строки:
1. `тег#id.класс1.класс2` (не больше двух классов, цвет `#B392F0`) и размер `Ш × В` (серый `#9DA5B4`).
2. Для `img`: `img натуральные Ш × В · webp · alt «…»`. Для остальных: `font Семейство вес · размер/межстрочный` (метка `#79B8FF`).
3. `color` с квадратиком цвета и значением `rgb(...)`.
4. `padding` - четыре числа, только если не все нули.
5. `↳ <Компонент>` - `data-ins` ближайшего предка, если он есть и это не сам элемент.

Подсказка встаёт под элементом на 10 px ниже и прижимается к краям окна с отступом 12 px. Если снизу не хватает места, она встаёт над элементом.

### 7.4 Производительность (обязательно)
- `getComputedStyle`, текст подсказки и её размер считаются **один раз на элемент**.
- При прокрутке, пока элемент выбран, и при движении внутри того же элемента только пересчитываются координаты: один раз за кадр (флаг `queued` + rAF), через `translate3d`. Ширина и высота рамок меняются, толщина границ - только при смене элемента.
- При `resize` элемент измеряется заново.
- HUD: `Ш×В окна`, `y scrollY`, `fps`. Счётчик кадров работает через rAF только пока инспектор включён, текст обновляется раз в 500 ms.

### 7.5 Вступление (скрины `d-light-11*`, видео 0-9 с)
Показывает посетителю, что инспектор есть. Запускается, только если мышь (fine pointer), нет reduced motion и страница открыта сверху (`scrollY < 40`). Старт через 1.5 s после загрузки.
1. Белый курсор-стрелка (26 px, с тенью) появляется в точке 82% ширины и 90% высоты окна.
2. Курсор по очереди подлетает к трём целям: третья строка заголовка, статус «Открыт к предложениям», кнопка «Смотреть работы». Переход 0.9s `cubic-bezier(.6,0,.2,1)`, точка - 62% ширины и 55% высоты цели. Через 900 ms после подлёта показываются рамки и подсказка этой цели. Шаг 2050 ms.
3. После трёх целей рамки гаснут, курсор летит к кнопке «Инспектор». Ещё через 900 ms курсор исчезает, а кнопка дважды мигает кольцом (`ping`, 1.2s).
4. Любая прокрутка больше 4 px, колесо, касание, клавиша или нажатие мыши сразу прерывают вступление. Оно никогда не мешает читать.

На сенсорных экранах вступления нет: кнопка инспектора мигает через 1.4 s после загрузки. При reduced motion нет ни того, ни другого.

## 8. Адаптив

Брейкпоинты те же, что в эталоне.

- **≤ 1100 px:** мета в 2 колонки; лид и кнопки во всю ширину; колонка роли в строке проекта скрыта; лента и таблица панели во всю ширину; цифры кейсов по 2; заметки в одну колонку; стек в 3 колонки.
- **≤ 820 px:**
  - строка проекта - год, название и описание столбиком, `+` справа по центру;
  - таблица панели в одну колонку, подпись над значением;
  - **лента скриншотов листается пальцем**: высота 300 px, `scroll-snap`, без полосы прокрутки, выходит под боковые поля экрана (скрин `m-*-03`);
  - превью у курсора отключено;
  - заголовок и абзац кейса во всю ширину, портрет до 340 px, стек в 2 колонки.
- **≤ 520 px:** мета, цифры кейсов и стек в одну колонку; в контактах значение и кнопка друг под другом; HUD инспектора переезжает вправо вверх под шапку.

На 360 px не должно быть горизонтальной прокрутки.

## 9. Мета и иконки

- `meta description`: «Frontend-разработчик на React и TypeScript. Работы: Almanac, Parkovich и другие проекты.» Текст согласовать с Никитой.

- Убрать из старого `index.html` `maximum-scale=1.0, user-scalable=no`: масштабирование нужно для доступности.

## 10. Доступность и скорость

- Строки проектов: настоящие `button` с `aria-expanded` и `aria-controls`. Скриншоты - кнопки с `aria-label`. Скриншоты кейсов - `img` с `role="button"`, `tabIndex 0`, Enter и Space.
- У всех картинок осмысленный `alt` (тексты в `markup.html` и `projects.ts`), а также `width` и `height`, чтобы ничего не прыгало.
- Скриншоты ниже первого экрана грузятся лениво (`loading="lazy"`).
- Оверлеи инспектора `aria-hidden`. Тост `role="status" aria-live="polite"`.
- Видимый фокус: 2 px `--accent` со смещением 3 px.
- `prefers-reduced-motion: reduce`: анимации и переходы выключены, нет вступления и пинга, тема меняется без заливки, плавная прокрутка выключена.
- Цели: Lighthouse mobile - скорость ≥ 90, доступность ≥ 95, лучшие практики ≥ 95, SEO ≥ 95. 60 fps при прокрутке с включённым инспектором и выбранным элементом при 4-кратном замедлении CPU (по HUD не ниже 55). CLS < 0.05.

## 11. Как принимать

Каждый PR сопровождается скриншотами сайта и эталона рядом в тех же точках из `reference/img/`.
- Размеры 1440×900 и 390×844, светлая и тёмная тема.
- Для анимаций и интерактива - запись рядом с соответствующим отрезком `reference/video/*`: вступление, превью у курсора, раскрытие строки, лайтбокс, смена темы, инспектор.
- Подсказка инспектора над тем же элементом даёт тот же текст, что в эталоне. Например, у `#title em` при 1440×900 в светлой теме: `em 905 × 156`, `font Wix Madefor Display 700 · 124/114`, `color rgb(98, 54, 224)`.

Пока разница видна глазом, не мержить. Если эталон и этот документ расходятся, прав эталон.

После последнего PR проверить всю страницу: 360 px без горизонтальной прокрутки, reduced motion, Lighthouse, FPS (§10), клавиатура (Tab проходит шапку, строки, скриншоты, кнопки, контакты; лайтбокс возвращает фокус).

## 12. Тесты

Playwright, Chromium, 1440×900 и 390×844:
- строка проекта раскрывается и сворачивается, `aria-expanded` меняется;
- лайтбокс открывается по скриншоту, закрывается по Esc, фокус возвращается;
- тема переключается и переживает перезагрузку;
- `I` включает инспектор; наведение на `#title em` показывает подсказку, которая начинается с `em` и содержит `Wix Madefor Display 700`; Esc выключает;
- в режиме инспектора клик по строке проекта её не раскрывает;
- «Скопировать» показывает тост;
- на 360 px `scrollWidth === clientWidth`;
- при reduced motion курсор вступления не появляется.

Unit-тесты (Vitest) для `nameOf` и разбора `measure` на фиксированном DOM.
